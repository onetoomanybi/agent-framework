# What This Code Does - Complete Summary

## ONE-LINER
This code lets AI agents running in Azure AI Foundry access and read files from Microsoft Fabric Lakehouses through a chat interface.

---

## THE PROBLEM IT SOLVES

Scenario: You have data in Fabric Lakehouses, and you want to run AI agents that can:
- List and explore files
- Read CSV data
- Answer questions about your data
- All through a conversational interface in Fabric notebooks

Before this code: Not possible - no way for agents to access Fabric data
After this code: Fully integrated - agents can see and read your data

## THREE FILES, THREE JOBS

### FILE 1: fabric_ai_foundry_client.py
WHERE: Runs in Fabric Notebooks (user writes this)
WHAT: Talks to the AI agent

Code does:
1. Authenticates to AI Foundry using Fabric credentials
2. Creates conversation thread with agent
3. Sends user message to agent
4. Gets and displays agent response

Example usage:
```python
client = AIProjectClient(endpoint, credential)
agent = client.agents.get_agent(agent_id)
response = run_agent_conversation(client, agent, "List files")
print(response)  # Agent's answer
```

AUTHENTICATION: Uses notebookutils.credentials (Fabric-specific)


### FILE 2: agent_lakehouse_tools.py
WHERE: Deployed as Azure AI Foundry tools (backend)
WHAT: The actual tool implementations that do the work

Code provides 3 tools:
1. list_lakehouse_files() - Lists files in lakehouse
2. read_csv_file() - Reads CSV file content
3. get_lakehouse_info() - Gets lakehouse metadata

Each tool:
- Takes workspace_id, lakehouse_id as input
- Creates DataLakeServiceClient connection
- Queries OneLake storage
- Returns JSON response

AUTHENTICATION: Uses managed identity with PowerBI/API scope


### FILE 3: function_app.py
WHERE: Deployed as Azure Function App (wrapper)
WHAT: HTTP endpoints that expose the tools

Code provides 4 endpoints:
1. POST /listFiles → calls list_lakehouse_files()
2. POST /readCSVFile → calls read_csv_file()
3. POST /getLakehouseInfo → calls get_lakehouse_info()
4. GET /health → returns {"status": "healthy"}

Each endpoint:
- Validates incoming JSON
- Calls corresponding tool
- Returns JSON response
- Has error handling

AUTHENTICATION: Azure Function auth level set to FUNCTION

---

## THE TWO AUTHENTICATION PATHS

PATH 1: Notebook → AI Foundry
What: Fabric notebook user authenticates to AI Foundry
Who: notebookutils.credentials (Fabric magic)
Token scope: ml.azure.com
Used by: fabric_ai_foundry_client.py

PATH 2: Azure Functions → Fabric Lakehouse
What: Function authenticates to Fabric storage
Who: DefaultAzureCredential (managed identity)
Token scope: https://analysis.windows.net/powerbi/api/.default
Used by: agent_lakehouse_tools.py

## CONCRETE EXAMPLE: USER WORKFLOW

Step 1: User in Fabric Notebook runs:
```python
response = run_agent_conversation(client, agent, 
    "List all CSV files and tell me their sizes"
)
```

Step 2: fabric_ai_foundry_client.py:
- Gets auth token from Fabric
- Creates thread in AI agent
- Sends message: "List all CSV files..."

Step 3: Azure AI Foundry Agent processes:
- Understands: "Need to list files"
- Decision: Call "listFiles" tool
- Makes HTTP POST to Azure Functions

Step 4: function_app.py receives POST:
- Validates: workspace_id, lakehouse_id present ✓
- Calls: list_lakehouse_files(workspace_id, lakehouse_id)

Step 5: agent_lakehouse_tools.py executes:
- Gets auth token (managed identity)
- Connects to OneLake with DataLakeServiceClient
- Lists all files in /workspace_id/lakehouse_id/Files/
- Filters .csv files
- Gets size of each file
- Returns JSON: [{"name": "data.csv", "size": 1024000}, ...]

Step 6: Response flows back:
- function_app.py → Azure AI Foundry → fabric_ai_foundry_client.py
- Agent formats: "Found 3 CSV files: data.csv (1.0 MB), ..."

Step 7: User sees response in Fabric Notebook

## THE CONNECTION TO OPENAPI

File: openapi_spec.json

This file defines the "menu" of tools available to the AI agent:
- Tool name: listFiles
- Tool description: "List files in Fabric lakehouse"
- Tool endpoint: https://functions.app.com/listFiles
- Tool parameters: workspace_id, lakehouse_id, path, extension

The AI agent reads this spec and knows:
- What tools are available
- What parameters each tool needs
- Where to call them
- What to expect back

## KEY INSIGHTS

1. **THREE LAYERS**
   - User layer: Fabric Notebook
   - Agent layer: AI Foundry
   - Tool layer: Azure Functions + Lakehouse Tools

2. **TWO AUTH TOKENS**
   - Notebook→Agent: Fabric notebookutils
   - Function→Lakehouse: Azure managed identity

3. **ONE DATA FLOW**
   - User question → Agent decision → Tool execution → Data retrieval → Response

4. **SECURITY MODEL**
   - Each component authenticates separately
   - Uses Azure managed identities where possible
   - Sensitive tokens never exposed to user code

5. **OPENAPI IS THE GLUE**
   - Tells AI agent what tools exist
   - Defines tool interfaces
   - Maps tool names to HTTP endpoints
